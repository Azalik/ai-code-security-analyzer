# 🛡️ AI Code Security Analyzer

Гибридный анализатор безопасности исходного кода (SAST + LLM), объединяющий детерминированный статический анализ на базе абстрактных синтаксических деревьев (AST) и контекстный аудит с помощью больших языковых моделей (LLM).

---

## 1. Актуальность и постановка задачи

**Актуальность:** Современная разработка ведётся в высоком темпе с активным использованием ИИ-ассистентов, из-за чего в кодовую базу регулярно попадают критические уязвимости из списка **OWASP Top 10** (инъекции команд, SQL-инъекции, небезопасная десериализация, утечки секретов). Классические статические анализаторы (SAST) точно указывают на строку с опасным вызовом, но генерируют много ложных срабатываний и не понимают бизнес-логику. С другой стороны, прямая отправка кода в LLM без предварительного разбора страдает от «галлюцинаций» и неточных номеров строк.

**Цель проекта:** Разработать веб-инструмент гибридного аудита безопасности кода для языков **Python** и **SQL**, минимизирующий ложные срабатывания и автоматически формирующий безопасные патчи.

**Задачи:**
1. Реализовать модуль детерминированного статического анализа для Python (обход AST-дерева) и SQL (сигнатурный анализ).
2. Интегрировать модуль контекстного ИИ-аудита с поддержкой облачных (Groq, OpenRouter, OpenAI) и локальных (Ollama) LLM-провайдеров.
3. Разработать механизм снижения галлюцинаций модели за счёт передачи результатов AST в системный контекст и фиксации низкой температуры генерации (`temperature = 0.15`).
4. Реализовать интерактивный веб-интерфейс на базе Streamlit с разделением отчёта на выявленные уязвимости, готовый патч и экспорт результатов в Markdown.

## 2. Архитектура решения

Анализ проходит в два последовательных этапа:

1. **Этап 1 — Детерминированный статический анализ (AST / Regex):**
   - Для **Python** исходный код парсится стандартным модулем `ast`. Анализатор обходит узлы дерева (`ast.Call`, `ast.Assign`) и с точностью до строки фиксирует:
     - RCE и инъекции команд: `eval()`, `exec()`, `os.system()`, `os.popen()`, `subprocess.*(..., shell=True)` (CWE-78, CWE-95);
     - Небезопасную десериализацию: `pickle.load/loads()`, `yaml.load()` без `SafeLoader` (CWE-502);
     - Слабую криптографию: `hashlib.md5()`, `hashlib.sha1()` (CWE-327);
     - SQL-инъекции через f-строки внутри `cursor.execute()` (CWE-89);
     - Жёстко закодированные секреты в переменных (`password`, `api_key`, `token`, `secret`) (CWE-798).
   - Для **SQL** выполняется построчный сигнатурный анализ на конкатенацию строк, тавтологии (`OR 1=1`), `UNION SELECT` и деструктивные DDL-команды (`DROP/TRUNCATE TABLE`).

2. **Этап 2 — Контекстный ИИ-аудит и генерация патча (LLM):**
   - Найденные AST-детектором уязвимости передаются в промпт как подтверждённые факты.
   - Модель оценивает итоговый уровень риска, проверяет контекст (включая логические уязвимости вроде IDOR, SSRF и Path Traversal, невидимые для AST) и возвращает единый исправленный блок кода, который автоматически извлекается парсером во вкладку **«Безопасный код (Патч)»**.

## 3. Структура репозитория

```text
ai-code-security-analyzer/
├── app.py                        # Основное веб-приложение Streamlit (AST + Regex + LLM)
├── requirements.txt              # Зависимости проекта
├── .env.example                  # Шаблон переменных окружения для API-ключей
├── .gitignore                    # Исключения Git (.env, __pycache__, venv)
├── README.md                     # Документация проекта
└── tests/                        # Набор показательных тестовых сценариев
    ├── 01_rce_and_secrets.py     # Явные уязвимости (детектируются AST + LLM)
    ├── 02_logic_idor_ssrf.py     # Скрытые логические уязвимости (детектируются только LLM)
    ├── 03_clean_safe_code.py     # Безопасный эталонный код (проверка на ложные срабатывания)
    └── 04_sqli_and_ddl.sql       # Уязвимый SQL-скрипт (детектируется Regex + LLM)
```

## 4. Установка и запуск

1. **Клонируйте репозиторий и перейдите в папку проекта:**
   ```bash
   git clone <url-вашего-репозитория>
   cd ai-code-security-analyzer
   ```

2. **Создайте виртуальное окружение и установите зависимости:**
   ```bash
   python -m venv venv
   # Windows:
   venv\Scripts\activate
   # Linux / macOS:
   source venv/bin/activate

   pip install -r requirements.txt
   ```

3. *(Опционально)* **Настройте ключи через `.env`:**
   Скопируйте `.env.example` в `.env` и укажите свой ключ (либо введите ключ прямо в боковой панели интерфейса):
   ```bash
   cp .env.example .env
   ```

4. **Запустите приложение:**
   ```bash
   streamlit run app.py
   ```

## 5. Методика тестирования и демонстрационные кейсы

В директории `tests/` подготовлены 4 сценария для проверки всех компонентов системы:

| Тестовый файл | Что проверяет | Ожидаемый результат AST/Regex | Ожидаемый результат LLM |
| :--- | :--- | :--- | :--- |
| `tests/01_rce_and_secrets.py` | Классические уязвимости (CWE-798, CWE-78, CWE-502, CWE-327) | Находит 5 уязвимостей с точными номерами строк | Подтверждает находки, объясняет риски, переписывает код на `os.getenv`, `subprocess.run` (списком), `json.loads`, `yaml.safe_load`, `sha256` |
| `tests/02_logic_idor_ssrf.py` | Скрытые контекстные уязвимости: **IDOR** (доступ к чужому профилю без проверки прав), **SSRF** и **Path Traversal** | **0 находок** (синтаксически вызовы выглядят обычными) | Выявляет IDOR, SSRF и Path Traversal за счёт понимания семантики и генерирует исправления с проверкой прав и валидацией URL/путей |
| `tests/03_clean_safe_code.py` | Эталонный безопасный код (проверка отсутствия False Positives) | **0 находок** | Подтверждает низкий уровень риска без ложных тревог |
| `tests/04_sqli_and_ddl.sql` | SQL-инъекции и опасные DDL-операции | Находит конкатенацию, `OR 1=1`, `UNION SELECT`, `DROP TABLE` | Предлагает параметризованные подготовленные выражения (`Prepared Statements`) |
